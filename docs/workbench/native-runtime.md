# Circle 桌面版前后端对接

本轮按用户的最新要求，先把 Circle 的桌面界面接到真实运行时，再处理其他四个对象的服务。此前“只做前端”的范围已经结束；旧的前端验收记录保留，不能当作本轮执行验证。

随后用户进一步明确：应用名称、描述和主界面都只使用 Circle，不出现 workbench。本轮应用只保留 Circle 功能，其他四个对象不注册入口，也不初始化预览服务。下文涉及平台对象的说明只表示后续边界，不属于当前交付。

Circle 范围收敛后的检查：原生宿主 11 项、命令界面 38 个入口与 45 项行为、运行时 16 项，以及开发和打包应用各 11 项实际流程通过。品牌检查验证应用名和窗口标题为 Circle，主界面无 workbench，也没有加载平台预览服务。此前 14/46 项包含四对象的记录按当时范围保留。

## 使用方式

打开应用后可以新建会话，在连接窗口填写 API 地址、密钥和模型。选择工作目录后，需要明确确认信任，Circle 才会加载其中的指令、技能和扩展并执行工具。输入、思考、工具参数和返回结果显示在同一个会话里；工具需要审批时，运行时会等待界面上的回复。

会话、分支和原始历史由 Circle 自己的 SQLite 存储管理。界面重载不会重新启动运行进程；应用重启后会恢复保存的会话。JSONL 导出使用核心的检查点图和内容校验记录，导入也走核心校验。屏幕上的撤销只隐藏内容，不回滚文件，也不改写保存的历史。

终端和 `!command` 使用 Circle 的用户命令执行机制；`!!command` 保留输出给操作者。模型、思考深度、计划模式、会话审批规则、后台工作、技能、命令、MCP 和运行时扩展连接到现有核心接口。命令模板中的 shell 片段由用户命令执行机制运行，输出保存在原始会话中，再展开到模型输入。界面里的长文本编辑器用于编辑下一条输入。

桌面数据放在应用自己的 `runtime-home` 中。密钥写入该目录的私有凭据文件，不进入前端缓存、审批历史或普通对话。首次安装无需提前运行命令行版本；尚未配置模型时，应用可以打开并完成连接设置。注销后不能继续使用缓存的模型连接发起请求。

## 程序之间怎样连接

Electron 主进程启动一个随安装包提供的 utility process。这个进程使用现有的交互式 `AgentRuntime`，拥有模型、工具、检查点、审批和后台工作。界面通过 preload 提供的具名接口提交操作，并读取带序号的真实状态。它不直接打开数据库，也不执行工具。

审批和问题回复绑定请求编号、会话、修订号和实际回调。过期、重复或来自错误会话的回复会被拒绝。近期请求在同一运行进程内重试时，会复用原回复；这不是跨重启的持久任务承诺。工具执行是否继续，仍由核心的执行路径决定，事件订阅只用于显示。

应用退出会等待核心关闭和所属进程退出。停止本地终端时，验证检查实际进程是否消失。对 SSH 等远程操作，取消本地调用依然不能证明远端已经停止；本轮没有连接真实设备。

## 验证

新增的运行时测试检查实际模型输入、原始历史、文件字节和私有凭据，而不只检查界面提示。桌面测试分别运行开发入口和打包应用，覆盖输入、审批、工具写文件、问题回复、界面重载、模型取消、真实 shell 进程取消、新建/选择会话、导入和重启恢复。

另外，测试从空目录启动普通模型路径，通过连接表单配置一个本地 HTTP 网关，检查实际 API 请求中的模型、思考深度和认证头。密钥不进入前端缓存。打包测试限制 PATH，验证运行进程不依赖外部 Node 或 Circle。开发数据、脚本模型和 HTTP 网关均为隔离资源，没有使用真实 Circle 数据、付费模型或生产设备。

执行记录在 `apps/desktop/artifacts/live/`，打包字节的记录在 `apps/desktop/out/artifact-receipt.json`。这些本地产物不写入 Git。持续集成保留各平台构建和验收记录。

## 这一阶段的边界

Circle 已接到真实核心。B/C/D/E 的界面组件和预览服务已从应用中移除。浏览器面板目前由操作者使用；设备连接和同一浏览器会话的 agent 控制属于后续服务对接。现有界面组件是随应用提供的第一方代码，不构成第三方插件商店或沙盒。

当前 `.app` 和 `.dmg` 是开发构建。签名、公证、发布更新通道和真实设备兼容性需要单独完成，不能由本轮本地验证推断。

本轮 macOS arm64 本地检查：原有核心 360 项、前端 21 项、原生边界 10 项和新增运行时 16 项通过；开发入口与打包应用各完成 11 项真实流程检查。前端预览的 38 个命令入口和 46 项界面检查保留为独立验证，不拿它们替代运行时检查。其他系统的构建结果由对应持续集成任务记录。

应用图标按用户要求调整：macOS 使用纯白底和彩色圆环，Windows 使用透明底圆环。实际生成的 macOS PNG 中心为纯白，Windows ICO 中心和角落的 alpha 均为零。
