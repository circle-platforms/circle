# Provider choices and model presets

`src/providers.ts` is the shared terminal and desktop provider registry. Its snapshot date is 2026-10-14. Each entry supplies the SDK base URL, protocol and either endpoint discovery or released preset ids. The selected provider id is saved as optional `auth.provider` metadata so runtime model lists use the same source. Regional and account-specific URLs can be edited before saving.

Endpoint discovery is used for OpenAI (Chat Completions and, as `OpenAI · Responses`, the Responses API at the same base), Anthropic, Groq, Gemini's OpenAI compatibility root, xAI, Mistral, Moonshot, MiniMax's two compatible roots, StepFun, SiliconFlow, Qianfan, DeepSeek's OpenAI root and Together. These entries carry no model presets. Discovery failures stay failures; the user may type a model id. See [models](../models.md) for paths and pagination.

The following providers use a small released selection of ids. This is not a complete directory or proof that the entered key can access them. Presets are chosen explicitly before discovery; no model-list request is made in that flow. Searching always permits a different id.

`glm-5.4` is the first id of both Zhipu entries since 2026-11-23, the day it was released, which is after the snapshot date above; the date was not moved because the other entries were not checked again. No vendor page or third-party snapshot is cited for it yet. Its evidence is a run through the Anthropic route (`https://open.bigmodel.cn/api/anthropic`) that day: it answered with the full tool list, ran tools, accepted the thinking levels `medium` and `high`, and carried a 37-minute session with subagents. The OpenAI-protocol entry carries the same id and was not run. models.dev listed it that day only under its coding-plan providers (`zhipuai-coding-plan` and `zai-coding-plan`), with a context window of 1,000,000 and an output limit of 131,072, and not under `zhipuai` or `zai`. A Circle with no newer copy of models.dev than the snapshot it ships with therefore does not know its window or price; see [models](../models.md#cost-and-context-in-the-footer).

The ids are maintained in source and change with Circle releases. Updating this registry does not update model prices, context windows or capabilities; those remain the separate `ModelCatalog` responsibility. Preset connections use these ids for `/models`, CLI `--list-models`, RPC and desktop model lists without a model-list request. Online and custom connections still request the endpoint's actual list and never fall back to presets after a discovery failure. Older settings without `auth.provider` are matched only against known preset URLs and protocols.

Vertex uses project/publisher prediction resources and dedicated authentication, so Circle does not offer a misleading generic Anthropic preset for it. Bedrock's SigV4 integration is also outside this registry. The Bedrock preset uses only the compatible API-key Messages route; it does not sign AWS requests or manage temporary tokens.
