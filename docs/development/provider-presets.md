# Provider choices and model presets

`src/providers.ts` is the shared terminal and desktop provider registry. Its snapshot date is 2026-10-14. Each entry supplies the SDK base URL, protocol and either endpoint discovery or released preset ids. The provider choice is a form choice, not saved account metadata; saved credentials and auth keep their format. Regional and account-specific URLs can be edited before saving.

Endpoint discovery is used for OpenAI, Anthropic, Groq, Gemini's OpenAI compatibility root, xAI, Mistral, Moonshot, MiniMax's two compatible roots, StepFun, SiliconFlow, Qianfan, DeepSeek's OpenAI root and Together. These entries carry no model presets. Discovery failures stay failures; the user may type a model id. See [models](../models.md) for paths and pagination.

The following providers use a small released selection of ids. This is not a complete directory or proof that the entered key can access them. Presets are chosen explicitly before discovery; no model-list request is made in that flow. Searching always permits a different id.

The ids are maintained in source and change with Circle releases. Updating this registry does not update model prices, context windows or capabilities; those remain the separate `ModelCatalog` responsibility. Presets never populate the runtime's discovered model cache. `/models`, CLI `--list-models` and desktop refresh still request the saved endpoint's actual list.

Vertex uses project/publisher prediction resources and dedicated authentication, so Circle does not offer a misleading generic Anthropic preset for it. Bedrock's SigV4 integration is also outside this registry. The Bedrock preset uses only the compatible API-key Messages route; it does not sign AWS requests or manage temporary tokens.
