# Settings

Circle keeps its settings in `settings.json` inside the data folder (`~/.circle` unless you set `CIRCLE_HOME`). Setup creates it. You can edit it by hand.

Read [Before you edit by hand](#before-you-edit-by-hand) first.

```json
{
  "version": 1,
  "initialized": true,
  "auth": {
    "protocol": "openai",
    "base_url": "https://gateway.example/v1",
    "model": "my-model",
    "api_key_ref": "api_key"
  },
  "trusted_folders": ["/Users/me/code/my-project"],
  "theme": "auto",
  "mcp_servers": [],
  "extensions": {},
  "credential_files": [],
  "trust_cert_files": [],
  "update_check": true
}
```

## Keys

Not used yet.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| `initialized`      | boolean         | `false`                                                      | Set by setup. `/logout` sets it back to `false`, and the next start shows setup.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| `auth.protocol`    | string          | `"openai"`                                                   | `openai` or `anthropic`. It decides which client talks to the endpoint. Read [Security](security.md#auto-mode) before choosing `auto`.                                                                                                                                                                                                                                                                                                                   |

| `double_escape`    | string          | `"tree"`                                                     | What `esc` twice on an empty input box opens: `tree` (the session tree), `fork` (the fork list) or `none`. `/settings` changes it.                                                                                                                                                                                                                                                                                                                                                                                                                                     |

## Project settings

A project can set a few things for its folder in `.circle/settings.json`, as pi's `.pi/settings.json` does:

```json
{
  "model": "step-5-preview",
  "default_thinking": "high",
  "credential_files": ["*.key"],
  "allowed_commands": ["make *"]
}
```

Only these keys are read: `model`, `default_thinking`, `enabled_models`, `double_escape`, `hide_thinking`, `theme`, `credential_files`, `allowed_commands` and `attribution`. They apply while Circle works in that folder, once it is trusted (sessions, `-p`, line mode and RPC mode), and are never written to your `settings.json`. `--model` on the command line wins over the project's `model`. `credential_files` and `allowed_commands` are added to yours, so a project can protect more files and allow more of its own commands, but never narrow either list. The endpoint, the key, MCP servers, extensions, trusted folders, `default_mode`, `workspace_folder` and `show_hook_allow` cannot be set by a project; a key Circle does not take is named in red at start (on standard error without the full-screen interface).

Hooks are not a key here. They live in `hooks.json` in the data folder and in `.circle/hooks.json` in a trusted project. A changed project file has to be approved again; the digest is `hook-trust.json` in the data folder, not a settings key. See [Hooks](hooks.md).

When you change one of these in a session (`/themes`, `/settings`, `alt+d` in `/models` or `/effort`, `tab` in `/models`, `/approvals add`), your choice is saved as yours and used from then on in this session.

## Crediting Circle in commits

In a git repository, Circle's prompt tells the model how to credit Circle when it creates or amends a commit or a pull request. The model adds the credit; Circle installs no git hook, does not rewrite an existing commit only to credit itself, and leaves the commits you make alone.

- With `author` `user`, the commit stays yours and ends with `Co-authored-by: Circle <346680939+circle-agent@users.noreply.github.com>`. GitHub shows the `circle-agent` account on the commit; its Contributors list counts only commit authors, so Circle is not listed there.
- With `author` `circle`, Circle is the commit author (`--author`) and you are added as `Co-authored-by`, from `git config user.name` and `user.email`. Circle then appears in the repository's Contributors list. Without a `user.email` the commit stays yours with the co-author line, so a commit never names Circle alone.
- `auto`, the default, is `circle` for runs nobody watches (`-p`, JSON, line and RPC mode) and `user` in the full-screen interface and the desktop application.

A pull request body gets the line `Generated with [Circle](https://github.com/circle-platforms/circle)`. `"attribution": {"enabled": false}` in your settings, in a project's `.circle/settings.json`, or the switch under settings → git in the desktop application turns all of this off; the model is then told not to add it.

## credentials.json

The API key is not in `settings.json`. It is in `credentials.json` next to it, a flat object of names and values:

```json
{ "api_key": "sk-..." }
```

`auth.api_key_ref` names which entry to use. Both files are readable only by you (mode `0600`; on Windows the folder's permissions protect them).

Secrets the model uses by name are in `secrets.json`, also next to it; see [Secrets by name](security.md#secrets-by-name).

## Before you edit by hand

- **Circle changes one key at a time.** When you change something in a session (`alt+d` in `/models` or `/effort`, `/themes`, `/settings`, `/trust`, `/login`, `/logout`), Circle reads the file from disk, changes that key and writes it back, so your hand edits and keys Circle does not know stay. The exception is `auth`: Circle writes back only `protocol`, `base_url`, `model` and `api_key_ref`, so the `mode` and `oauth_provider` an older release wrote are dropped. The running session goes on with what it read at start until you run `/reload`.
- **A malformed file stops Circle** at start with `settings could not be read` and exit code `2`, also for `circle --init`. Keep a copy before you edit.
- **`circle --init` replaces only the connection**: `auth` (endpoint, protocol, model). It also clears `enabled_models` when the endpoint changes. See [CLI](cli.md#setting-up-again).

## Reloading

`/reload` re-reads `settings.json`, the project's `.circle/settings.json` and `credentials.json`, reconnects MCP servers, reloads extensions, and rebuilds the model. It applies `theme` and re-reads `allowed_commands`. It also re-reads `hooks.json` (yours, the project's and any skill's) for later events. It does not run `session_start` hooks again. It does not re-read `credential_files`, and it does not re-apply `default_mode` (a session-start setting). It is refused while a turn is running.
