# Browser issue implementation and verification

All implementation and checks below use the isolated `issue-two-end-fixes/circle` worktree, temporary Circle homes/data directories, synthetic pages and either ScriptedModel or loopback HTTP model gateways. No production equipment, paid models, real browser profile or real Circle data was used. Verification finished before the user authorized publishing the issue/PR update. Platform checked here: macOS arm64, bundled Node 24.19.0, installed Chrome and development Electron.

## Reproduction before the fix

- **#44 (TUI/ChromeBrowser, original report Windows):** the unchanged direct-attachment regression passed on this Mac; it was not a Windows reproduction. A new real Chrome/loopback attachment fixture delayed delivery of `Browser.download*` events by 1600 ms. Before the fix the navigation returned no download approval (`undefined` instead of `download`). On this platform the real `Page.navigate` response contains `errorText: "net::ERR_ABORTED"` and `isDownload: true`. This proves the event-order failure locally, not the original Windows machine's exact cause.
- **#51 (shared DOM extraction):** a visible `span` with only an `addEventListener('click', …)` handler, without pointer cursor/role/tabindex, appeared as plain `...` text with no ref. An inline-handler span and a pointer-cursor span did receive refs. The omitted control's handler produced a real loopback request when triggered in the fixture. Neither adapter previously exposed a usable coordinate fallback.
- **#54 (desktop lifecycle):** an opener-created popup calling `window.close()` reproduced the main-process exception `Cannot read properties of undefined (reading 'isDestroyed')`. The new development Electron lifecycle regression was red before the fix.
- **#55 (desktop address draft):** the new tab-change state regression was red: an editing latch from a failed navigation caused the new blank tab to return `undefined` instead of an empty address. The full native scenario subsequently verified invalid navigation → new blank tab → select old real tab.
- A packaged smoke run exposed an intermittent first-tab initialization race: an address typed before the first `t1` state arrived could be cleared as if the user had switched tabs. The extracted state-transition regression reproduced an empty result instead of the entered loopback URL before the correction. First attachment now preserves the editing latch; actual later tab changes still clear it. The parent independently reran the same packaged smoke and saw 11 checks pass before this race correction, so that successful rerun alone was not treated as proof the race was fixed.
- Coordinate review found two further actual effect failures. On both real Chrome and Electron a button's `mouseenter` changed “Show details” to “Delete configuration”, but the old action pressed it without a destructive decision. Likewise, scrolling a nested main-document container changed the hit button while an old screenshot remained accepted. Both new native fixtures were red before their corrections.

## Resulting behavior

- Download navigation consumes the CDP `isDownload` signal and distinguishes aborted navigation from loaded pages. Both adapters wait at most 3 seconds, with cancellation, for a download-start event when a navigation was a download/aborted. A missing event after an explicit download response is an error; an aborted navigation without a download is never reported as `Loaded`. Keeping/discarding bytes and per-site approvals retain their existing behavior.
- `browser_click_at(x, y, screenshotId)` is available through the shared tools/protocol/catalog. Screenshots identify their CSS viewport and latest capture id; the normal image output still reports scaling. Both adapters hit-test the composed DOM and send real pointer events. Tabs, documents, DOM changes, scrolling, viewport resize, new screenshots and browser handoff invalidate old captures. Same-origin frames/open shadow roots are inspected; cross-origin frame targets are refused.
- Unknown and destructive coordinate targets require a one-time decision in manual mode even after a site's browser control was allowed. The decision binds the actual hit target, coordinates and capture; there is no remembered coordinate permission. Model arguments cannot carry the approval token. Certificate warnings refuse coordinate clicks and retain the existing ref-based gate. Coordinate actions are explicitly left out of recorded scripts. No general page-evaluate tool was added.
- Desktop tabs hold a stable WebContents reference. Closure is idempotent, removes the tab, wakes waiters, settles dialogs/certificate/permission requests and publishes the remaining state even if native cleanup finds an already-gone page. Shutdown shares the cleanup path. TUI's separate CDP target cleanup is covered with the same self-close behavior and cookie preservation.
- Desktop address editing belongs to the session/tab. A tab change always synchronizes its real URL, including empty `about:blank`. An older navigation's late rejection cannot overwrite a newer tab/session or a newer navigation in the same tab. Same-tab loading events preserve a draft the person is composing.
- Coordinate input sends mouse movement first and then rechecks the capture and hit target's identity, origin, role, name, recognized status and geometry before pressing. Hover changes require a fresh screenshot and any resulting destructive target requires its one-time decision. Captures include synchronous nested scroll offsets across same-origin documents and open shadows, plus scroll event invalidation, so immediately changed container offsets cannot slip through an unprocessed scroll event.
