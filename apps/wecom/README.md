# 企业微信私人聊天适配器

同一个企业机器人服务所有已绑定的成员。自建应用负责扫码身份，智能机器人使用官方长连接 SDK。成员在 Hub 设置页先用本人账号发起绑定。登录回调路径为 `/console/identity/callback`。

使用 Node 24，在此目录按锁文件运行 `npm ci`。以服务账户启动 `node adapter.ts <Hub 数据目录的 bot-runtime 子目录>`。匹配版本的 Circle 宿主运行 `circle remote-bot <同一子目录>`。目录权限为 0700。两个进程分别持有私有套接字；配置和模型密钥由 Hub 的密钥库管理。部署的服务管理器须保持两个进程常驻。

管理员在设置页分别保存模型、自建应用、私聊机器人。适配器访问 Hub 的地址使用部署的 HTTPS 来源，临时本地测试可用回环 HTTP。保存通道后处于停用状态，管理员启动后才持有该 Bot ID 的长连接。正式替换前须核对原连接持有者、已受理的任务和所有业务验收结果。

每个单聊输入按 Bot ID、成员与平台消息编号去重，并按同一发件人的批次元顺序（FIFO）投递至 Hub。文件和随后的说明在同一批输入中提交；若合并后的文本超过 16000 字符或附件超过 8 个，适配器会自动拆分为顺序批次投递，每个分块按 `<platformId>:<序号>` 生成确定性请求标识；单条文本超长、附件超过 8 个或媒体地址非 `https:` 的单聊帧会记录日志并按 `(发件人, 原因)` 5 分钟限频发送中文拒收说明，不再静默丢弃。入站媒体下载默认仅允许 `DEFAULT_WECOM_MEDIA_HOSTS`（`qyapi.weixin.qq.com`、`wwcdn.weixin.qq.com`、`wework.qpic.cn`、`wx.qlogo.cn`）且禁止重定向；该默认主机列表来源状态为**未知**（尚未在真实企业微信长连接回调帧中实测核验，可通过 `serveChannel` 选项 `mediaHosts`、环境变量 `CIRCLE_WECOM_MEDIA_HOSTS`、`configure` 帧 `mediaHosts` 或 `ChannelSession` 构造参数 `mediaHosts` 覆盖）。入站媒体在下载和写入本地暂存前会先核对企业成员身份并请求 Hub `authorize`；若身份解析或 `authorize` 返回永久拒收（如 `403`），适配器不会发起媒体下载或写入本地暂存；仅当 `authorize` 通过或因临时故障（网络错误或 `401`/`408`/`429`/`5xx`）无法取得结果时，才在暂存限额内下载与解密并落盘至本地 `<bot-runtime>/staging/<sha256>`（`0700` 目录内 `0600` 文件），并在临时故障期间保留批次附件引用，待恢复后从本地暂存重传；仅在企业微信媒体下载/解密失败、超出暂存上限或 Hub 永久拒收（`400`/`403`/`413`/`422`）时丢弃附件并追加未接收提示。本地暂存默认上限可通过 `serveChannel` 选项配置：`maxStagingBytes`（默认 `536870912`，即 `512 MiB`）、`maxStagingFiles`（默认 `128`）、`maxSenderStagingBytes`（默认 `134217728`，即 `128 MiB`）、`maxStagingAgeMs`（默认 `7200000`，即 `2 小时`）；全局字节数与文件数按 `sha256` 去重统计（含活跃批次与在途下载），单发件人字节数按该发件人活跃批次与在途下载累计，超限时拒绝新暂存并按 5 分钟窗口向发件人发送限频中文提示。活跃批次超过 `maxStagingAgeMs` 保留时间后会在刷新时清除附件、立即清理过期暂存文件并向发件人发送超时提示。暂存清理会在引用它的全部批次进入终态或过期清理后再删除对应文件，且会为正在写入的 `.part` 临时文件保留 15 分钟保护窗口。Hub 文件传输总超时为 `900s`（`900000` 毫秒），同时设有无进展停滞超时 `transferStallTimeoutMs`（默认 `30s` / `30000` 毫秒，可通过 `serveChannel` 选项 `transferStallTimeoutMs` 配置）：分块上传或读取响应期间若超过该时间无字节进展即中止并按临时故障重试。企业微信身份查询临时故障（HTTP `408`/`429`/`5xx` 或 `-1`/`45009`/`45011`/`45033`/`42001`/`40014`/`42007`）与 Hub 临时不可达（网络错误或 `401`/`408`/`429`/`5xx`）均仅计入 `transient_attempts` 并按指数退避（上限 60 秒）持续重试，不占用非临时故障的 5 次隔离上限；同一批次相同错误原因的重试警告按 5 分钟窗口限频；被永久拒收或非临时故障连续失败 5 次时记为 `failed`、记录日志并尽力向成员发送中文说明（按 `(发件人, 原因)` 5 分钟限频，发送失败时记录警告日志）。

主动私聊发送先在宿主占用一条待送达消息，再向 SDK 请求发送。缺少确认时保留送达未知，重启后不会自动重发。在 Hub 核实绑定并检查账号仍然启用后才返回收件人和内容。对宿主发出的 `notice` 事件，适配器先校验 `verifyDeliveryIntent(item)`，再按提示码转换为简体中文提示。群帧在下载附件或查询成员前即被忽略。

验证范围说明：

- `npm test`（`adapter.test.ts`）使用合成企业身份、合成 WebSocket 帧与模拟 fetch，覆盖协议去重、通知本地化、重试与告警限频、隔离与 FIFO 顺序、凭证刷新与脱敏、媒体限流与先鉴权后暂存、暂存配额与过期清理及文件传输停滞超时。
- `npm run test:paired`（自包含模拟 Hub 回环）验证官方 `@wecom/aibot-node-sdk` 的 `WSClient`、Circle `RemoteBot` 宿主与模拟 Hub 路由（含单聊消息、`帮助` 中文提示、加密入站附件与出站附件回传、已停用账号拒收）。
- `node test-paired.mjs <Hub 源码目录>` 在上述基础上连接真实 Hub 服务与 PostgreSQL，额外核验 Hub `member-notification-intent@1` / `member-notification-receipt@1` 持久化、成员读写隔离及 `channel-staging` 晋升与清理。以上检查均可重复执行，无需真实租户凭据。

发送适配器核对 Hub 登记的载荷 SHA-256 和长度。确认记录包含平台应答编号摘要和返回码。客户端显示平台确认或送达未知。成员实际阅读需要单独的现场证据。
